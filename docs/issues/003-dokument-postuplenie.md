# Issue 003: Документ «ПоступлениеТоваров» + регистр «ТоварныеЗапасы» + проведение

**Статус:** в работе
**Спринт:** Фаза 1, занятие 3
**Исполнитель:** Palit (Litiy4)

## Контекст (почему это сердце учёта)

Справочники хранят «кто/что», документы фиксируют «что случилось» (событие с датой и номером).
Но ни те, ни другие не отвечают на вопрос: **«сколько товара сейчас на складе?»** Для этого существует
**регистр накопления** — «счётчик», в который документы записывают **движения** (приход/расход).
**Проведение документа** = запись его движений по регистрам.

Строим первое звено учёта запасов: поступление товара увеличивает остатки.

## Требования

### 1. Документ `ПоступлениеТоваров`

Реквизиты шапки:
- `Контрагент` — `СправочникСсылка.Контрагенты`
- `Склад` — `СправочникСсылка.Склады`

Табличная часть `Товары` (реквизиты):
- `Номенклатура` — `СправочникСсылка.Номенклатура`
- `Количество` — Число(10, 2), неотрицательное
- `Цена` — Число(10, 2)
- `Сумма` — Число(12, 2)

Формы — автогенерируемые.

### 2. Регистр накопления `ТоварныеЗапасы`

- Вид регистра: **Остатки**
- Измерения: `Номенклатура` (`СправочникСсылка.Номенклатура`), `Склад` (`СправочникСсылка.Склады`)
- Ресурсы: `Количество` — Число(10, 2), `Сумма` — Число(12, 2)

### 3. Проведение (первый код на встроенном языке!)

В модуль объекта документа поместить:

```bsl
Процедура ОбработкаПроведения(Отказ, Режим)
	Движения.ТоварныеЗапасы.Записывать = Истина;
	Для Каждого СтрокаТовары Из Товары Цикл
		Движение = Движения.ТоварныеЗапасы.Добавить();
		Движение.ВидДвижения = ВидДвиженияНакопления.Приход;
		Движение.Период = Дата;
		Движение.Номенклатура = СтрокаТовары.Номенклатура;
		Движение.Склад = Склад;
		Движение.Количество = СтрокаТовары.Количество;
		Движение.Сумма = СтрокаТовары.Сумма;
	КонецЦикла;
КонецПроцедуры
```

## Шпаргалка исполнителю

1. **Документ:** Конфигуратор → Документы → Добавить → `ПоступлениеТоваров`. Вкладка **Данные**:
   реквизиты `Контрагент` и `Склад` (типы — ссылочные, как в issue 002); ниже «Табличные части» →
   добавить `Товары` → в ней 4 реквизита (у `Количество` на вкладке типа числа снимите галку «Неотрицательное»? —
   наоборот, оставьте по умолчанию; точность 2, длина по ТЗ).

   > **Уточнение (по вопросу исполнителя):** реквизиты табличной части добавляются в **вложенную** ветку
   > «Реквизиты» **внутри** `Товары` (правый клик по ней → Добавить), а не в верхнюю ветку «Реквизиты» (это шапка).
   > `НомерСтроки` — стандартный реквизит табличной части, руками не добавляется, не трогаем.
   > Для числовых реквизитов в конструкторе типа задаются Длина (10 или 12) и Точность (2).
2. **Регистр:** Регистры накопления → Добавить → `ТоварныеЗапасы`. В свойствах сверху выбрать
   **Вид регистра: Остатки**. Вкладка **Данные**: Измерения (`Номенклатура`, `Склад`), Ресурсы
   (`Количество` Число(10,2), `Сумма` Число(12,2)).
3. **Код:** в дереве правый клик на `ПоступлениеТоваров` → **Открыть модуль объекта** → вставить код из ТЗ
   (обратите внимание: отступы — табуляцией, это стандарт 1С) → **Ctrl+S → Да**.
4. **F5** (Предприятие) → Поступление товаров → Создать: контрагент, склад, 2–3 строки
   (товары из справочника, количество/цена/сумма руками) → **Провести и закрыть**.
5. **Движения:** откройте документ из списка — в форме проведённого документа есть ссылка/кнопка
   **«Движения документа»** (или Ещё → Движения). Убедитесь: жёлтая стрелка вверх = приход, заполнены
   измерения и ресурсы.
6. Создайте второе поступление на **другой** склад. Убедитесь, что в движениях склады разные.
7. Закройте 1С → сообщите «готово».
